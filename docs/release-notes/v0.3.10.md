# F.R.I.D.A.Y. 0.3.10: updates ship whole, satellites wait for the server, and a failed update rolls back completely

This release replaces v0.3.9, which must not be installed. It carries everything from v0.3.9 plus the fix for the update that left a satellite without a voice program.

- The release now declares what its satellite package contains, so any server version packs it complete.
- A satellite only gets a package built by a server at least as new as the release.
- A failed satellite update restores the system files it touched, not just the program folder.
- Migrations fail loudly when they cannot do their job.

This is a **pre-release** (alpha channel). It reaches stable after 48 hours of soak and the live checks below.

## Highlights
- **The release declares its satellite package.**
  - `ota/release.json` has a new `package.satellite` section (`paths` and `system`) listing what the package carries.
  - The server agent reads it from the release it is packing, so an older agent packs a newer release complete.
  - A file the release declares but the tree lacks fails the build, and nothing is written.
  - Releases without the section (older tags, rollback targets) still pack with the built-in lists.
- **Satellites wait for the server.**
  - A satellite is offered an update only after the server agent has installed that same version (`waiting_server`).
  - Each satellite package records who built it (`built_by`) and when it was first offered. A package built by an older agent is rebuilt before use, unless a device may already hold it.
  - A server older than the release refuses to build the satellite package (`server_older`), including for a manual image build.
  - A manual install on a satellite also asks the server to install when it is behind.
  - A satellite held back for more than 1 hour sends one push to the owner, naming the version and the reason. It repeats at most once a day.
- **A failed update rolls back whole.**
  - Before the migrations, the satellite snapshots the system files the install will write.
  - On a health failure, a manual rollback or an interrupted update, it puts them back byte for byte, removes the ones it created, reloads systemd and udev, then switches the program folder as before.
- **Migrations fail when they cannot do their job.**
  - 0004 no longer records itself as done when its audio files are missing from the release.
  - New 0005 installs the audio files (board selector, per-board ALSA files, udev rule, sendspin drop-in, silence service) and fails if any is missing.
- **Everything in v0.3.9** (XVF3800 support, USB watchdog, beam lock, `friday.build_image`, Marketplace self-update, promotions seen right away) is included.

## Changes by area
- **Server agent:**
  - The packager reads `package.satellite` from the release, with a two-pass archive.
  - `built_by` and `offered` markers in the package metadata.
  - Server-first gate on satellite offers and image builds.
  - Waiting push, at most once a day.
- **Satellite agent:** snapshot and restore of system files around an activation, and `prune` keeps the last snapshot.
- **Migrations:** 0004 fails on a missing source; 0005 reinstalls the audio files.
- **Release:** `ota/release.json` carries the package declaration; the manifest is 0.3.10.

## Breaking changes / Compatibility
- **v0.3.9 is withdrawn and must not be installed.** Its satellite package was incomplete.
- **A satellite rolled back from v0.3.9 heals by updating to v0.3.10.** It installs the missing audio files and starts the voice program by itself.
- **The integration still needs one manual install if it is on 0.3.5.** Accept the Marketplace's warning first, then install 0.3.10. Later releases update themselves.
- **Gate B and `built_by` only act from the next release on.** The first rollout of v0.3.10 is packed by the v0.3.9 agent, which has neither. That package is complete, and the v0.3.10 agent keeps it instead of rebuilding it.
- The whole rollback protects activations run by this release's apply, so it starts with the update after v0.3.10.
- Everything noted for v0.3.9 still applies (`/etc/asound.conf` becomes a link; images flashed with 0.3.8 do not speak on an XVF3800).
