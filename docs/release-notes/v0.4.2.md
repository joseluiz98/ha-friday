# F.R.I.D.A.Y. 0.4.2: announcements on the satellites

This is an **alpha** pre-release. It goes to the alpha satellite, the server and the integration first. Stable devices get it after the 48 h soak and the promotion gate below.

- The satellites can now speak the house announcements ("the washer finished", "coffee is ready"): a chime, then the fixed text in her voice. Nothing is paraphrased and no conversation opens.
- Every release now carries the satellite's top-level sounds, so a satellite that predates a tone gets it.

## New features
- **`friday.announce` service.** `message` (1 to 500 characters) and an optional `device_id` list of satellite devices; with no device, every F.R.I.D.A.Y. satellite device in Home Assistant's device registry. A device that is not a satellite is refused ("Only satellites can announce."). It returns the per-satellite answers (`vou_tocar`, `na_fila`, `calado`, `expirado`, `sem_suporte`, `erro`, `reenviando`) as the service response and writes one logbook line per call, also when it fails ("Announcement failed: <code>"). Meant to be called with `continue_on_error: true` from house scripts, next to the Echo announcement.
- **The satellite decides when to play.** An announcement waits while a conversation is open, a timer alarm is ringing, a wake word is being claimed or a delivery is being opened, and plays when she is free (order: alarms, then deliveries already queued, then announcements). It waits at most 5 minutes from the request: the bot sends the age of the request on every attempt, so a late resend is not played (`expirado`). In do-not-disturb it is dropped (not queued). With the microphone muted it still plays. While the satellite boots it is held until the boot finishes.
- **Alert volume, chime and ducking.** Chime (`sons.anuncio`) then speech, both at the alert volume. Music on the MK1 is ducked as for a reminder. Several announcements play in order, one chime each. When it ends she goes back to rest: no microphone, no "listening" light.
- **Interrupting.** An active wake word cuts the announcement and opens a normal conversation. Any button stops it, with no conversation. Room speech does not stop it.
- **Same text, no new cost.** The speech is cached on the VM (key = voice + TTS model + speaking rate + text, 200 files, oldest out), so a repeated announcement does not call the TTS again.
- **Voice, TTS model and speaking rate in one place.** `voice_settings.tts` is the single source for every TTS call (announcements and the whisper mode). The voice is the one the conversation uses, and the speaking rate (slow / normal / fast) set in Home Assistant applies to announcements too.
- **Whisper replies now follow the speaking rate set in Home Assistant.** Before, a whispered reply always used the normal rate.

## Changes by area
- **Integration:** new `friday.announce` service (schema, satellites resolved from the device registry, 30 s wait for the server, response relayed, logbook line on success and on failure).
- **Server agent (VM host):** new `announce` command that posts to the bot with a bearer token kept in `/srv/friday/state/announce.token` (or `FRIDAY_TOKEN_ANNOUNCE`, as in the bot; created on the first command, mode 600, never printed). A token problem fails that command only (`token_unavailable`), never the agent. Every agent (server and satellites) now runs each command in its own task, so a slow command no longer holds the others or the connection's pings.
- **Voice gateway (VM):** new `POST /announce`. Validates the text and the satellites, makes the speech with the Gemini TTS (resampled to 48 kHz stereo), caches it, sends it to each satellite in parallel (cable IP, then Wi-Fi IP, with the `X-Announcement-Age` header) and answers within 18 s. A satellite that did not answer is retried every 15 s for up to 5 minutes (connection errors only; a 404 or a 4xx is final). One NDJSON line per announcement in the deliveries log (`tipo: "anuncio"`, with the cache hit or miss and the TTS time), one per satellite outcome (`tipo: "anuncio_final"`), and the TTS call goes into the cost log. TTS settings are centralized in `voice_settings.tts`; the model comes from `FRIDAY_TTS_MODEL` (`FRIDAY_WHISPER_TTS_MODEL` is still accepted).
- **Satellite program:** announcement queue and playback in the maestro, `/announce` on the local port (body is the WAV, `X-Announcement-Id` and `X-Announcement-Age` headers, 16 MB cap), files in `~/anuncios/<id>.wav` removed after playing or expiring, and an id the satellite already holds is not queued twice. New sound `sons.anuncio` (`anuncio_elevenlabs.wav`, with a synthetic `anuncio_a.wav` as a fallback). No migration: the new key appears by itself.
- **Packaging:** every release bundle now carries the top-level `satellite/sounds/` (12 files plus the new chime, about 9 MB), not only `onboarding/`.

## Known limits
- Do-not-disturb turned on while an announcement is playing lets it finish.
- A bot restart loses the pending retries of an announcement.
- An id re-sent after it finished playing plays again.
- An explicit or default target that the bot does not know (a satellite device left in Home Assistant after it was retired) fails the whole call as `invalid`.
- A satellite on an older version answers 404 and is logged as `sem_suporte`; the MK2 stays so until this release is promoted to stable.

## Promotion gate (stable)
- [ ] On the MK1 at rest, an announcement plays: chime, then speech, at the alert volume.
- [ ] During a conversation it waits, then plays when the conversation ends.
- [ ] In do-not-disturb it is dropped: the answer is `calado` and no file is left in `~/anuncios`.
- [ ] Sent during a reboot, it is held and plays after the boot finishes.
- [ ] An active wake word cuts it and opens a conversation; any button stops it.
- [ ] The same text twice: the second one is a cache hit in the bot log.
- [ ] With the speaking rate set to slow and to fast, she does not read "Fale devagar:" or "Fale rápido:" aloud.
- [ ] With the rate slow/fast, a whispered reply does not say "Fale devagar/rápido" aloud.
- [ ] An announcement whose text contains a wake word ("sexta-feira") does not cut itself.
- [ ] Music playing on the MK1 is ducked during the announcement and comes back after it.
- [ ] A satellite that predates the release gets the new chime file after the update.

## All changes
- `friday.announce` service, `announce` server command and `POST /announce` on the bot
- Announcement queue and playback on the satellite, with the new chime `sons.anuncio`
- TTS voice, model and rate centralized in `voice_settings.tts`
- Release bundles carry the top-level satellite sounds
