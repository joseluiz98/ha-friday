# F.R.I.D.A.Y. 0.4.2: Home Assistant shows when the alpha will be promoted

This is an **alpha** pre-release. It goes to the alpha satellite, the server and the integration first. Stable devices get it after the 48 h soak and the promotion gate below.

- The Server device now has a sensor that says when the alpha being tested will become stable, and why it has not yet if something is in the way.
- Nothing changes on the satellites or in the voice.

## New features
- **Alpha promotion sensor.** A new diagnostic sensor on the Server device, **Alpha promotion**. Its state is the time the alpha under test will be promoted to stable, which Home Assistant shows as "in 1 day". It is "unknown" when the alpha has no running clock (not installed yet, or failed) or when there is no alpha to track.
- **Attributes.** `tag` (the release tracked), `status`, `started_at`, `promotes_at`, `soaked_hours` (hours since the clock started, or until the promotion once it happened), `newer_stable` (a stable release newer than the tag already exists) and `alphas` (every alpha still waiting, newest first, each with its own status and promotion time).
- **Statuses.** `waiting_install` (no alpha satellite has installed it yet, so there is no clock), `soaking` (counting the 48 h), `ready` (48 h passed, the promotion happens in the next 10-minute cycle or on the next GitHub retry), `failed` (an alpha device reported a failure; it is never promoted), `promoted` and `superseded` (a stable release newer than it appeared first).
- **Two alphas in a row each keep their own clock.** The sensor follows the newest one and lists both in `alphas`. An alpha older than the newest stable release drops out of the list, even one that no satellite ever installed: it can only end `superseded`. When no alpha is waiting, the sensor keeps showing the last one decided, with its result.
- Instead of "hours remaining", the state is the promotion time itself (Home Assistant renders the remaining time) and `soaked_hours` is the elapsed time.

## Changes by area
- **Server agent (VM host):** new `Orchestrator.alpha_promotion()` and the descriptor `ota_alpha_promotion`, pushed with the other OTA entities on every OTA cycle (no timer of its own, so `soaked_hours` moves about every 6 minutes at most). The newest-stable computation of the promotion step moved into one helper shared with the sensor; promotion behavior is unchanged.
- **Integration:** no code change. It builds the sensor from the server's descriptor.
- No change to the store format and no migration.

## Promotion gate (stable)
- [ ] After the alpha satellite (MK1) installs v0.4.2, the **Alpha promotion** sensor shows `soaking` for v0.4.2 and a promotion time 48 h after the install.
- [ ] Before the MK1 installs it, the status is `waiting_install` and the state is "unknown".
- [ ] After 48 h, the sensor shows `promoted` for v0.4.2 and the release is stable on GitHub.

## All changes
